BUG 1 [LOW] - main.py - Stale log path in startup dialog
======================================================================
File: smart_hardware_diagnostic_scanner/main.py, lines 18-22

Current code:
    messagebox.showerror(
        "Startup failed",
        f"Smart Hardware Diagnostic Scanner failed to start.\n\n{exc}\n\n"
        "Install dependencies with:\n  pip install -r requirements.txt\n\n"
        "See logs/scanner.log for details.")

Problem:
  Says "See logs/scanner.log" but scanner/logging_config.py now logs to a
  per-user location:
    Windows: %LOCALAPPDATA%\SmartHardwareDiagnosticScanner\logs\scanner.log
    Linux:   ~/.local/share/SmartHardwareDiagnosticScanner/logs (or $XDG_DATA_HOME)
    macOS:   ~/Library/Application Support/SmartHardwareDiagnosticScanner/logs
    Fallback: temp dir / cwd logs
  README.md (Features section) already documents the new location.
  main.py did not follow. User will look in the wrong folder after a
  startup failure.

Fix:
    messagebox.showerror(
        "Startup failed",
        f"Smart Hardware Diagnostic Scanner failed to start.\n\n{exc}\n\n"
        "Install dependencies with:\n  pip install -r requirements.txt\n\n"
        "See %LOCALAPPDATA%\\SmartHardwareDiagnosticScanner\\logs\\scanner.log for details.")

Note (not a bug):
  Second except block calls messagebox without ensuring a Tk root.
  Works via Tk implicit root, silently no-ops headless. Already guarded
  by try/except: pass, so acceptable.

BUG 5 [MEDIUM / HYGIENE] - requirements.txt - Optional deps forced mandatory
======================================================================
File: smart_hardware_diagnostic_scanner/requirements.txt

Current:
    psutil>=5.9
    matplotlib>=3.7        # comment says "Optional" but pip WILL install it
    pyinstaller>=6.0; sys_platform == "win32"
    pytest>=7.0            # test-only, should not ship to end users

Problem:
  Contradicts README Section 5:
    pip install psutil pytest            # minimal (no charts)
    pip install psutil matplotlib pytest # with charts
  and contradicts graceful-degradation logic:
    scanner/charts.py HAS_MPL fallback
    scanner/hardware.py HAS_PSUTIL fallback
  End users get forced matplotlib + pytest installs. On brand-new
  interpreters (3.13/3.14) matplotlib wheels can lag, breaking
  `pip install -r requirements.txt` for users who do not even need charts.

Fix - split or mark optional (pick one approach):

Option A - extras in requirements.txt:
    psutil>=5.9
    matplotlib>=3.7; extra == "charts"
    pytest>=7.0; extra == "test"
    pyinstaller>=6.0; sys_platform == "win32" and extra == "packaging"

Option B - keep runtime minimal, add requirements-dev.txt:
  requirements.txt:
    psutil>=5.9
  requirements-dev.txt:
    -r requirements.txt
    matplotlib>=3.7
    pytest>=7.0
    pyinstaller>=6.0; sys_platform == "win32"

Optional version bump for 3.14 support:
  psutil>=6.1, matplotlib>=3.9 (old wheels lag on new interpreters;
  your own comment in requirements.txt already warns about this).

Latent nit (outside requested scope, in scanner/charts.py lines 8-19):

  TkAgg backend is broken, a different exception escapes and crashes import.
  Safer: except Exception.
  Current:
    try:
        import matplotlib
        matplotlib.use("TkAgg")
        ...
    except ImportError:
  Suggested:
    except Exception:
